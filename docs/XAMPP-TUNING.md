# تجهيز خادم XAMPP لمئات المستخدمين في الوقت نفسه

الكود صار خفيفاً على الخادم، لكن إعدادات XAMPP الافتراضية مصممة لجهاز مطوّر واحد. هذه الإعدادات تُضبط **مرة واحدة**، وكل خطوة فيها تعديل سطر أو سطرين.

> قبل أي تعديل: خذ نسخة من الملفات الثلاثة (`httpd.conf` و`php.ini` و`my.ini`). بعد التعديل أعد تشغيل Apache وMySQL من XAMPP Control Panel.
>
> للتحقق: سجّل الدخول بحساب المشرف، ثم افتح زر قاعدة البيانات في الأعلى، نافذة «المزامنة والخادم»، قسم «صحة الخادم». كل بند فيه علامة ✓ أو ⚠ مع طريقة الإصلاح.

---

## 1. Apache — `C:\xampp\apache\conf\httpd.conf`

احذف علامة `#` من بداية هذه الأسطر:

```
LoadModule deflate_module modules/mod_deflate.so
LoadModule headers_module modules/mod_headers.so
```

وتأكد أن مجلد htdocs يسمح بملف `.htaccess`:

```
<Directory "C:/xampp/htdocs">
    AllowOverride All
```

في نهاية الملف أضف:

```
ServerName localhost
KeepAlive On
MaxKeepAliveRequests 500
KeepAliveTimeout 5
```

## 2. عدد الطلبات المتزامنة — `C:\xampp\apache\conf\extra\httpd-mpm.conf`

في قسم `mpm_winnt_module`:

```
<IfModule mpm_winnt_module>
    ThreadsPerChild        400
    MaxConnectionsPerChild   0
</IfModule>
```

القيمة الافتراضية 150 تكفي نحو 150 طلباً في اللحظة نفسها. القيمة 400 تكفي مئات المستخدمين بهامش أمان.

## 3. PHP — `C:\xampp\php\php.ini`

تفعيل OPcache يُغني PHP عن إعادة قراءة الكود في كل طلب:

```
zend_extension=opcache
opcache.enable=1
opcache.memory_consumption=128
opcache.max_accelerated_files=4000
opcache.validate_timestamps=1
opcache.revalidate_freq=60

realpath_cache_size=4096k
realpath_cache_ttl=600
memory_limit=256M
post_max_size=64M
upload_max_filesize=32M
```

## 4. MySQL / MariaDB — `C:\xampp\mysql\bin\my.ini`

في قسم `[mysqld]`:

```
max_connections=500
max_allowed_packet=64M
innodb_buffer_pool_size=512M
innodb_log_file_size=128M
skip-name-resolve
innodb_flush_log_at_trx_commit=2
```

- **`skip-name-resolve`**: يمنع البحث في DNS عن اسم كل جهاز يتصل، وهذا سبب شائع لبطء الاتصال في الشبكات المؤسسية. بعد تفعيله استخدم `127.0.0.1` وليس `localhost` في صلاحيات مستخدم MySQL.
- **`innodb_buffer_pool_size`**: اجعلها نحو ربع ذاكرة الخادم (512M لخادم 4 جيجابايت، و1G لخادم 8 جيجابايت).
- **`innodb_flush_log_at_trx_commit=2`**: تسرّع الحفظ كثيراً، خاصة على القرص التقليدي (HDD). الثمن: قد تضيع آخر ثانية من التعديلات إذا انقطعت الكهرباء عن الخادم فجأة (وليس عند إعادة تشغيل MySQL). إذا لم يكن ذلك مقبولاً فاترك القيمة 1.

## 5. ملف `config.php`

```php
'host' => '127.0.0.1',
```

في Windows يحاول `localhost` الاتصال عبر IPv6 أولاً، فيتأخر كل طلب. الكود يحوّلها تلقائياً، لكن كتابتها صراحة أوضح.

## 6. مكافح الفيروسات في Windows

أضف المجلد `C:\xampp` إلى استثناءات Windows Defender (أو برنامج الحماية المستخدم). بدون ذلك يُفحص كل ملف PHP وملف قاعدة بيانات مع كل طلب. هذا من أكثر أسباب بطء XAMPP شيوعاً.

## 7. الخادم نفسه

- يُفضَّل قرص SSD، ومعالج بأربعة أنوية وذاكرة 8 جيجابايت أو أكثر.
- لا تشغّل الخادم على جهاز يستخدمه أحد للعمل اليومي.
- اجعل MySQL وApache يعملان كخدمات Windows (زر Svc في XAMPP Control Panel)، حتى يعملا تلقائياً بعد إعادة التشغيل.

## 8. العمل على http و https معاً

النظام لا يفرض بروتوكولاً معيناً: يعمل على `http://` و`https://` في الوقت نفسه بلا أي تعديل في ملفاته. ويختار عنوان الخادم حسب الصفحة المفتوحة، ويصحح تلقائياً أي عنوان قديم محفوظ ببروتوكول آخر. يبقى فقط تفعيل https في Apache:

1. **تأكد أن SSL مفعّل** (مفعّل افتراضياً في XAMPP). في `C:\xampp\apache\conf\httpd.conf` يجب ألا تبدأ هذه الأسطر بعلامة `#`:
   ```
   LoadModule ssl_module modules/mod_ssl.so
   Include conf/extra/httpd-ssl.conf
   ```
2. **أنشئ شهادة باسم الخادم وعنوانه.** المتصفحات الحديثة ترفض الشهادة التي لا تحتوي حقل `subjectAltName`. من موجه الأوامر:
   ```
   cd C:\xampp\apache
   bin\openssl req -x509 -nodes -days 3650 -newkey rsa:2048 -config conf\openssl.cnf ^
     -keyout conf\ssl.key\server.key -out conf\ssl.crt\server.crt ^
     -subj "/CN=sqapa-server" -addext "subjectAltName=DNS:sqapa-server,IP:192.168.1.10"
   ```
   ضع اسم الخادم الفعلي وعنوان IP الخاص به بدل `sqapa-server` و`192.168.1.10`. الملفان يحلان محل شهادة XAMPP الافتراضية، فلا يلزم تعديل `httpd-ssl.conf`.
3. **أعد تشغيل Apache** من لوحة XAMPP، وافتح المنفذ 443 في جدار حماية Windows للشبكة الداخلية.
4. **اجعل الأجهزة تثق بالشهادة** حتى لا تظهر رسالة «الاتصال ليس خاصاً»:
   - **الأفضل:** يوزّع قسم الأنظمة الملف `server.crt` عبر Group Policy إلى «Trusted Root Certification Authorities».
   - **يدوياً على جهاز واحد:** انقر الملف نقراً مزدوجاً ← Install Certificate ← Local Machine ← «Trusted Root Certification Authorities».
   - إن كان لدى الأكاديمية جهة شهادات داخلية (Active Directory Certificate Services)، فاطلب منها شهادة للخادم، وتثق بها كل الأجهزة تلقائياً.
5. **جرّب:** `http://sqapa-server/IT/` و`https://sqapa-server/IT/`، فيجب أن يعمل الاثنان.

ملاحظات:
- المتصفح يعامل `http` و`https` كموقعين منفصلين. لذلك يسجّل المستخدم دخوله في كل منهما مرة، ويحتفظ المتصفح بنسخة محلية لكل منهما، لكن البيانات واحدة على الخادم.
- على `http` يستخدم النظام تشفيره الداخلي لكلمات المرور، لأن المتصفح لا يتيح أدوات التشفير الحديثة إلا على `https`. ويعمل النسخ إلى الحافظة بطريقة بديلة.
- **التحويل الإجباري إلى https (موصى به بعد تثبيت الشهادة على كل الأجهزة):** في ملف `.htaccess` بمجلد النظام كتلة جاهزة معطّلة بعنوان «التحويل الإجباري إلى https». أزل علامة `#` من أسطرها الخمسة، فيُحوَّل كل من يفتح `http://` إلى `https://` تلقائياً، ولا تمر كلمات المرور ورموز الجلسات على الشبكة نصاً مقروءاً. يلزم أن يكون `mod_rewrite` مفعّلاً في `httpd.conf` (السطر `LoadModule rewrite_module modules/mod_rewrite.so` دون `#`). بعد التحويل يسجّل كل مستخدم دخوله مرة واحدة على `https`.

## 9. نسخ Chrome القديمة

النظام يعمل من **Chrome 60** فما فوق:
- أُضيفت بدائل للدوال الحديثة التي لا تعرفها النسخ القديمة.
- حُوّلت قاعدة البيانات الاحتياطية في الذاكرة لتعمل عليها.
- أُضيفت بدائل لتنسيقات المواضع الحديثة، حتى لا تختل النوافذ قبل Chrome 87.

إن ظهرت رسالة «التحميل يستغرق وقتاً أطول من المعتاد»، ففي آخرها سطر صغير بالإنجليزية فيه نسخة المتصفح وسبب التعطل الفعلي. صوّره وأرسله للدعم. ويُنصح دائماً بتحديث Chrome من `chrome://settings/help`.

## 10. فتح النظام باسم بدل عنوان IP

مثال: بدل `http://192.168.12.100/IT/` يصبح الرابط `http://it.sqapa.local/` أو `http://it/`.

لا يلزم أي تعديل في ملفات النظام أو `config.php`:
- الصفحة تحمّل ملفاتها بمسارات نسبية.
- عنوان الخادم (API) يُحسب تلقائياً من الرابط المفتوح.
- الخادم لا يقيّد اسم المضيف.

التعديل في مكانين فقط:

### أ) ربط الاسم بعنوان الخادم (DNS)

اختر طريقة واحدة:

1. **خادم DNS الخاص بالنطاق (الأفضل، ويطبَّق على كل الأجهزة):**
   1. على خادم النطاق: Server Manager ← Tools ← DNS.
   2. Forward Lookup Zones ← اسم نطاقكم ← زر الفأرة الأيمن ← New Host (A or AAAA)…
   3. Name: `it`، وIP address: `192.168.12.100` ← Add Host.

   الأجهزة المنضمة للنطاق تفتح بعدها `http://it/` أو `http://it.<اسم النطاق>/`.
2. **بدون خادم نطاق:** أضف «Static DNS entry» بالاسم والعنوان نفسيهما في الراوتر أو الجدار الناري الذي يوزّع DNS على الأجهزة.
3. **للتجربة أو لأجهزة قليلة:** افتح Notepad كمسؤول (Run as administrator)، ثم افتح الملف `C:\Windows\System32\drivers\etc\hosts`، وأضف في آخره:
   ```
   192.168.12.100    it.sqapa.local    it
   ```

**للتحقق** من أي جهاز: `nslookup it` يجب أن يُظهر `192.168.12.100`. إن لم يظهر نفّذ `ipconfig /flushdns` وأعد المحاولة.

يجب أن يكون عنوان الخادم ثابتاً: إعداد يدوي أو حجز في DHCP.

### ب) إزالة `/IT` من الرابط — `C:\xampp\apache\conf\extra\httpd-vhosts.conf`

أضف في آخر الملف، وضع اسمك بدل `it.sqapa.local`:

```apache
# 1) العنوان القديم http://192.168.12.100/IT/ وlocalhost يبقيان كما هما. يجب أن يبقى هذا القسم أولاً
<VirtualHost *:80>
    ServerName 192.168.12.100
    DocumentRoot "C:/xampp/htdocs"
</VirtualHost>

# 2) الاسم الجديد يفتح النظام مباشرة بدون /IT
<VirtualHost *:80>
    ServerName it.sqapa.local
    ServerAlias it
    DocumentRoot "C:/xampp/htdocs/IT"
    <Directory "C:/xampp/htdocs/IT">
        Options -Indexes +FollowSymLinks
        AllowOverride All
        Require all granted
    </Directory>
</VirtualHost>
```

بعد الإضافة:
1. تأكد أن السطر `Include conf/extra/httpd-vhosts.conf` في `httpd.conf` لا يبدأ بعلامة `#`.
2. افحص الإعداد من موجه الأوامر: `C:\xampp\apache\bin\httpd.exe -t`. يجب أن تظهر `Syntax OK`.
3. أعد تشغيل Apache من لوحة XAMPP.

القسم الأول ضروري: Apache يعامل أول قسم كافتراضي لأي اسم غير مذكور. بدونه يتوقف العنوان القديم وlocalhost.

### بعد التغيير

- **أول مرة:** كل جهاز يسجّل الدخول مرة واحدة على الرابط الجديد، ويحمّل البيانات من الخادم، لأن المتصفح يعامل الاسم الجديد كموقع جديد. البيانات على الخادم لا تتأثر.
- **أبقِ العنوان القديم يعمل فترة انتقالية** (أسبوعين مثلاً)، من أجل:
  - المفضلات والاختصارات القديمة.
  - روابط الاستبيانات التي نُسخت سابقاً.
  - أي جهاز عمل دون اتصال وفيه تعديلات لم تُرفع: يُفتح على العنوان القديم مرة ليرفعها.
- **بعد الفترة الانتقالية (اختياري):** حوّل صفحة النظام القديمة إلى الاسم الجديد بإضافة هذا السطر داخل القسم الأول:
  ```apache
  RedirectMatch 302 "(?i)^/it(/|/index\.html)?$" "http://it.sqapa.local/"
  ```
  يحوّل صفحة الدخول فقط، ويحتفظ بباقي الرابط (مثل `#/tickets/…`). طلبات المزامنة لا تتأثر، فتستطيع الأجهزة المتأخرة رفع تعديلاتها.
- **سياسات المتصفح:** إن كانت المتصفحات مُدارة بسياسة تسمح «ببيانات المواقع» لعناوين محددة فقط، فأضيفوا الاسم الجديد إليها. بدون ذلك تظهر رسالة «التخزين محجوب».
- **إن كنتم تستخدمون https** (القسم 8): أعيدوا إنشاء الشهادة بحيث تحتوي الاسم الجديد في `subjectAltName`، مثل `DNS:it.sqapa.local,DNS:it,IP:192.168.12.100`.
- **اختيار الاسم:**
  - تجنّب `.dev` و`.app`، لأن المتصفحات تفرض عليها https.
  - تجنّب أسماء نطاقات حقيقية على الإنترنت لا تملكونها.
  - إن كانت هواتف آيفون ستفتح النظام، فتجنّب الأسماء المنتهية بـ `.local`.

> جُرِّب هذا الإعداد على Apache 2.4 بترتيب مجلدات XAMPP نفسه:
> - الاسم الجديد والاسم المختصر يفتحان النظام ويزامنان.
> - العنوان القديم `/IT/` وphpMyAdmin يعملان كما هما، و`config.php` يبقى محجوباً.
> - سطر التحويل يحوّل الصفحة فقط ويحتفظ بباقي الرابط.

## 11. النسخ الاحتياطي المجدول على الخادم

النسخة من «مركز النسخ» في النظام تعتمد على متصفح مفتوح. الأداة `tools/backup.php` تعمل على الخادم نفسه دون متصفح:
- تنسخ قاعدة البيانات بـ`mysqldump` (نسخة متسقة دون إيقاف النظام) وتضغطها.
- تنسخ مجلد المرفقات (`files_dir` في `config.php`).
- تضع الاثنين في ملف واحد مؤرخ، مثل `sqapa_2026-10-08_0200.zip`.
- تحذف النسخ الأقدم من المدة المحددة.
- تكتب النتيجة في `backup.log`.

تقرأ بيانات القاعدة من `config.php` الموجود، فلا تُكتب كلمة المرور مرة أخرى.

**الإعداد مرة واحدة:**
1. انسخ `tools\backup.php` إلى مجلد خارج `htdocs`، مثل `C:\xampp\sqapa-tools\`، حتى لا يُفتح من المتصفح.
2. جرّبه من موجه الأوامر:
   ```
   C:\xampp\php\php.exe C:\xampp\sqapa-tools\backup.php C:\xampp\htdocs\IT\api\config.php D:\IT-Backups 30
   ```
   المعاملات بالترتيب:
   - مسار `config.php`.
   - مجلد النسخ (يُفضّل قرص آخر غير قرص النظام).
   - عدد أيام الاحتفاظ.
3. جدوله يومياً: «جدولة المهام» (Task Scheduler) ← Create Basic Task ← Daily (مثلاً 2:00 صباحاً) ← Start a program:
   - **Program:** `C:\xampp\php\php.exe`
   - **Arguments:** `C:\xampp\sqapa-tools\backup.php C:\xampp\htdocs\IT\api\config.php D:\IT-Backups 30`
   - في خصائص المهمة: «Run whether user is logged on or not».
4. انسخ مجلد النسخ دورياً إلى جهاز آخر أو قرص خارجي، فالنسخة على الخادم نفسه لا تحمي من عطل قرصه.
5. جرّب الاسترجاع مرة على جهاز تجريبي:
   - فك الضغط.
   - استرجع القاعدة: `mysql -u root -p اسم_القاعدة < db.sql` (بعد فك `db.sql.gz`).
   - انسخ مجلد `files` إلى مكانه.

نتيجة كل تشغيل في `backup.log` داخل مجلد النسخ. وتُظهر «جدولة المهام» رمزاً غير الصفر عند الفشل.
